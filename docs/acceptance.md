## Отдельный репозиторий

Исходники перенесены в `WhoamiTitle/node-todo-final` из портфолио. Перенос не является новым
деплоем: приведённые ниже production-проверки относятся к прежним релизам портфолио.
Сначала выполнить [план миграции](standalone-migration.md), отдельно выпустить согласованный commit,
проверить API и сохранность БД, затем обновить ZIP и ссылку для форума. Старый архив остаётся
комплектом для прежнего опубликованного релиза, а не подтверждением публикации нового репозитория.

Тестовые записи интерфейса удалены. Персональное дело сохранено. Скриншоты находятся в игнорируемом `output/playwright/`; токен на них не виден. Firefox/WebKit и опубликованный HTTPS-стенд в этом этапе не проверялись.

```bash
npm run check
npm run test:integration
npm audit
```

`test:integration` требует работающий локальный MongoDB из Compose. Тесты отказываются работать с удалённым `MONGO_ADMIN_URI`. Они создают случайную БД `todo_test_*`, пользователей и коллекции, а затем удаляют только собственные тестовые ресурсы. Коллекция приложения `node_todo_final.tasks` не очищается.

В dev-toolchain закреплён `minimatch@11.0.1` через npm override: версия 10 из дерева ESLint затронута [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249). Используемые ESLint glob-операции проверены запуском линтера; зависимость не входит в production. Override нужно пересмотреть, когда ESLint обновит собственное ограничение версии. В runtime используются только Express и MongoDB driver с их зависимостями.

- Unit/HTTP: точные поля, статусы и типы ответов; auth до разбора тела; неверный JSON; лишние поля; UUID; Unicode title; runId; done только boolean; 404/204; разделение владельцев; trailing slash; безопасные ошибки.
- MongoDB: уникальность id, валидатор; отдельный клиент reviewer читает и меняет те же документы; повторная инициализация сохраняет уже созданное через API дело целиком; удаление согласовано в обе стороны.
- Полномочия: app/reviewer не могут читать другую коллекцию или системных пользователей, удалять `tasks` целиком, создавать новых пользователей.
- Перезапуск: тест останавливает реальный дочерний Node.js-процесс и запускает заново; созданные документы остаются доступными.
- Отказ БД: настоящий недоступный MongoDB endpoint приводит к ограниченному по времени ответу 503, без строки подключения в ответе.

## Ручная проверка интерфейса

1. Получить локальный API-токен командой `npm run token --silent`, ввести его в форме входа. Не публиковать вывод и не включать в скриншоты.
2. Проверить логин и ФИО. После входа выбран список «Мои дела» (`manual`). Проверить точное название `Итоговая работа 24.10.2026: vasiliy_only1f`; добавить через форму, только если записи нет.
3. Открыть другой список по коду, создать дело, переименовать, отметить, снять отметку, удалить с подтверждением. Вернуться в «Мои дела» без ввода кода. Проверить пустой список, длинное название и узкий экран.
4. Через отдельного DB-пользователя изменить название и нажать «Обновить из базы данных». Не использовать API вместо независимого DB-клиента.
5. Перезапустить Node, войти заново; проверить сохранность manual-дела. Проверить клавиатуру, закрытие диалогов и возврат фокуса.

Для проверки опубликованной версии необходимы те же шаги через HTTPS и разрешённый преподавателю канал. Скриншоты, fake repository и локальные тесты этот этап не заменяют.

Команды только чтения: `uname -srm`, `pg_isready -h pg -p 5432`, SELECT `current_user/current_database`, SELECT прав текущей роли, версии имеющихся Node/Mongo, `sockstat` для двух кандидатных портов. Результат: FreeBSD 14.5-STABLE amd64; PostgreSQL `studs` доступен пользователю `s507353`; обе привилегии CREATE ROLE/CREATE DB false; Node 24.21.0; MongoDB 8.0.29. Порты 30356/30357 свободны. Команда `quota` недоступна, численная квота не установлена. Никаких изменений на Helios не внесено.

Сайты Timeweb Cloud и Atlas проверены GET-запросом с TLS: HTTPS 200. Это только доступность сайтов, не успешная регистрация, предоставление бесплатного кластера или реальное DB-подключение. Источники и ограничения находятся в таблице README.

При локальном запуске MongoDB 8.0.29 отказалась стартовать на ядре Docker Desktop `7.0.14-linuxkit`. Использован актуальный образ ветки 8.0 с фиксированным digest. Это отдельная Linux-проблема, а не доказательство несовместимости пакета FreeBSD на Helios. [Официальные release notes MongoDB](https://www.mongodb.com/docs/manual/release-notes/8.0/).
